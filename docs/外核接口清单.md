# 外核已完成接口清单

本文记录当前外核对 EL0 libOS 暴露的接口，以及 EL1 内部已经完成的 GICv2/IRQ 支撑接口。

## EL0 调用约定

EL0 通过 `svc #0` 进入 EL1。

当前 libOS 封装约定：

```text
x8 = syscall 编号
x0 = arg0
x1 = arg1
x2 = arg2
返回值 = x0
```

实现位置：

- EL1 syscall 分发：`kernel/src/trap.rs`
- EL0 syscall 封装：`libos/src/main.rs`

## 已完成 syscall

| 编号 | 名称 | 输入 | 返回 | 说明 |
| --- | --- | --- | --- | --- |
| 2 | `SYS_PUTS` | `x0 = 用户字符串 VA`, `x1 = 长度` | `0` | EL1 逐字节读取 EL0 字符串并通过当前 UART 输出。 |
| 5 | `SYS_EXIT` | `x0 = 退出码` | 不返回 | 清理当前 EL0 任务资源，撤销用户映射，释放 code/stack 页，禁用并清理 IRQ。 |
| 6 | `SYS_MAP_MMIO` | `x0 = MMIO PA`, `x1 = size`, `x2 = EL0 VA` | `0` 成功；非 0 失败 | EL1 校验该物理地址已由 DTB 登记为允许 MMIO，再映射为 EL0 Device memory。 |
| 7 | `SYS_IRQ_BIND` | `x0 = GIC INTID` | `0` 成功；非 0 失败 | 将已授权的 SPI 绑定到当前任务。当前只允许 DTB 发现的 UART IRQ。 |
| 8 | `SYS_IRQ_WAIT` | 无 | `INTID`；失败返回 `u64::MAX` | EL1 临时启用当前任务绑定的 IRQ，保持 PSTATE.I 屏蔽，执行 `WFI`，读取 `GICC_IAR` 后返回实际 INTID。 |
| 9 | `SYS_IRQ_ACK` | `x0 = INTID` | `0` 成功；非 0 失败 | 校验当前 active IAR token 与 INTID 匹配，然后写 `GICC_EOIR`。 |
| 10 | `SYS_IRQ_UNBIND` | `x0 = INTID` | `0` 成功；非 0 失败 | 禁用该 IRQ 并从当前任务绑定表移除。若该 IRQ 正处于 active 状态，会先写 EOIR。 |

## syscall 错误语义

### `SYS_MAP_MMIO`

| 返回值 | 含义 |
| --- | --- |
| `0` | 映射成功 |
| `1` | `paddr` 或 `user_va` 非 4KB 对齐，或 `size == 0` |
| `2` | `paddr` 不在 EL1 保护表允许的 MMIO 区域内 |
| `3` | 当前没有有效 stage-1 根页表 |
| `4` | 当前任务不存在或 MMIO 记录表已满 |

映射粒度会向上取整到 4KB。保护检查使用 `protect::lookup(paddr)`，也就是只要求起始物理地址落入已登记 MMIO 区域；这是为了支持 UART 这类 `reg` 小于 4KB 的设备。

### `SYS_IRQ_BIND`

| 返回值 | 含义 |
| --- | --- |
| `0` | 绑定成功 |
| `1` | INTID 超出 `u32`，或 INTID 小于 32；当前只支持 SPI |
| `2` | 当前任务不存在，或 INTID 未被 EL1 授权 |
| `3` | 重复绑定，或当前任务 IRQ 绑定表已满 |

绑定后 EL1 会配置该 SPI：

- 初始禁用；
- 清 pending；
- priority 设为 `0x80`；
- target CPU 设为 CPU0；
- 触发方式设为 level-triggered。

### `SYS_IRQ_WAIT`

失败返回 `u64::MAX`。

失败条件：

- 上一个 IRQ 已经读出 `GICC_IAR`，但 EL0 尚未调用 `SYS_IRQ_ACK`；
- 当前任务没有绑定任何 IRQ。

成功路径：

```text
EL1 设置 PSTATE.I = 1
EL1 enable 当前任务所有 bound IRQ
EL1 执行 dsb sy; wfi
设备 IRQ 唤醒 CPU
EL1 主动读取 GICC_IAR
如果 INTID 属于当前任务:
    保存完整 IAR token
    禁用 bound IRQ
    返回 INTID 给 EL0
否则:
    写 GICC_EOIR 丢弃该 IRQ
```

这里不需要线程和异步用户态 handler。IRQ 只在 `SYS_IRQ_WAIT` 内开启，EL0 普通执行期间不会被设备 IRQ 异步打断。

### `SYS_IRQ_ACK`

| 返回值 | 含义 |
| --- | --- |
| `0` | ACK 成功，已写 `GICC_EOIR` |
| `1` | INTID 超出 `u32`，或没有 active IRQ，或 INTID 与 active IAR token 不匹配 |

`ACK` 必须在 EL0 清掉设备侧中断源之后调用。例如 PL011 接收中断路径中，EL0 先读空 RX FIFO，再清 PL011 的 `RXI/RTI/error` 中断源，最后调用 `SYS_IRQ_ACK`。

### `SYS_IRQ_UNBIND`

| 返回值 | 含义 |
| --- | --- |
| `0` | 解绑成功 |
| `1` | INTID 超出 `u32`，或该 INTID 未绑定 |

## IRQ 模型

当前 IRQ 模型是 v1 单任务模型：

- 单 EL0 任务；
- 无线程；
- 最多记录 16 个 IRQ 绑定；
- 同一时间最多允许 1 个已确认但未 ACK 的 IRQ；
- 当前只授权一个 UART IRQ；
- EL0 不能任意绑定 GIC INTID；
- 任务退出时自动禁用所有绑定 IRQ，并对未完成 active IRQ 写 EOIR。

状态保存在 `kernel/src/task.rs`：

```text
irq_bindings[16]  // 当前任务绑定的 INTID
irq_binding_count // 绑定数量
active_iar        // 完整 GICC_IAR token，0 表示没有 active IRQ
```

## GICv2 支撑接口

实现位置：`kernel/src/gic.rs`。

| 接口 | 作用 |
| --- | --- |
| `init(gicd_pa, gicc_pa)` | 初始化 GIC Distributor 和 CPU Interface，打开 GICD/GICC，设置 `GICC_PMR = 0xff`。 |
| `authorize_uart_irq(intid)` | 登记唯一允许 EL0 绑定的 UART INTID。 |
| `is_authorized(intid)` | 检查 INTID 是否是授权 UART IRQ。 |
| `configure_spi(intid, trigger_level)` | 配置 SPI 优先级、目标 CPU、触发方式，并保持初始禁用。 |
| `enable_spi(intid)` | 写 `GICD_ISENABLER` 使能 SPI。 |
| `disable_spi(intid)` | 写 `GICD_ICENABLER` 禁用 SPI。 |
| `read_iar()` | 读取 `GICC_IAR`。 |
| `acknowledge()` | 读取 `GICC_IAR`，过滤 spurious interrupt，返回完整 IAR token。 |
| `write_eoir(iar_token)` | 写 `GICC_EOIR`，完成 priority drop/deactivate。 |
| `intid(iar_token)` | 从完整 IAR token 中取低 10 位 INTID。 |

当前支持的 GICv2 compatible：

- QEMU virt：`arm,cortex-a15-gic`
- Raspberry Pi 5：`arm,gic-400`

## DTB 与权限

EL1 启动时从 DTB 完成三类登记：

1. 登记所有可映射 MMIO 区域，供 `SYS_MAP_MMIO` 查询；
2. 解析 GICD/GICC `reg`，初始化 GICv2；
3. 解析 stdout UART 的 `interrupts`，转换为 GIC INTID，并调用 `authorize_uart_irq()` 授权。

EL0 libOS 也会读取同一份只读 DTB：

1. 解析 `/chosen/stdout-path` 或常用 alias；
2. 找到 stdout UART 节点；
3. 读取 UART `reg` 并按父总线 `ranges` 翻译成 CPU 物理地址；
4. 读取 `interrupts`，把 GIC 3-cell specifier 转换为 INTID；
5. 用 `SYS_MAP_MMIO` 映射 UART；
6. 用 `SYS_IRQ_BIND` 绑定 UART IRQ。

GIC interrupt specifier 转换规则：

```text
<0 hwirq flags>  // SPI: INTID = 32 + hwirq
<1 hwirq flags>  // PPI: INTID = 16 + hwirq
```

当前 IRQ syscall 只接受 SPI，也就是 `INTID >= 32`。

## 当前已验证链路

### QEMU virt

UART IRQ 已验证可用：

```text
EL0 bind UART INTID 33
EL1 SYS_IRQ_WAIT 返回 33
EL0 读 PL011 RX FIFO
EL0 原样写回 UART
EL0 清 PL011 中断源
EL0 SYS_IRQ_ACK
```

### Raspberry Pi 5

当前 DTB 发现 UART10：

```text
UART PA = 0x107d001000
size    = 0x200
INTID   = 0x98
```

Pi5 上已经确认：

- `SYS_MAP_MMIO` 成功；
- `SYS_IRQ_BIND` 成功；
- `SYS_IRQ_WAIT` 能被 PL011 `RTI` 唤醒；
- `SYS_IRQ_ACK` 能完成 GIC EOI。

当前 libOS 为 Pi5 增加了 TX FIFO 等待，因为 `arm-pl011-uart::write_word()` 是非阻塞写，EL1 日志较多时可能导致 TX FIFO 满而丢回显字节。

## 当前未完成或刻意不支持

- 多任务；
- 线程；
- 用户态异步 IRQ handler 回调；
- 任意设备 IRQ 授权；
- GICv3；
- RP1 级联中断控制器；
- MSI；
- 通用 capability 表；
- 用户页申请/释放 syscall。
