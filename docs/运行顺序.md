# 代码执行顺序

## 最短结论

`kernel/src/main.rs` 是整个内核的入口。

启动后代码按这个顺序跑：

```text
UEFI
→ kernel/src/main.rs::main()              // EL2 boot shim
→ kernel/src/boot_info.rs                 // EL2 填 BootInfo
→ UEFI console                            // EL2 / EBS 前日志
→ kernel/src/vectors.rs::install_el2()    // EL2 安装异常向量
→ kernel/src/trap.rs::enter_el1_kernel()  // EL2 eret 到 EL1
→ kernel/src/kmain.rs::el1_main()         // EL1 外核
→ kernel/src/vectors.rs::install_el1()    // EL1 安装异常向量
→ kernel/src/mem.rs                       // EL1 初始化/使用物理页分配器
→ kernel/src/mmu.rs                       // EL1 先开 identity stage-1
→ kernel/src/dtb.rs                       // EL1 静默找 UART，再完整解析 DTB
→ kernel/src/uart.rs                      // EL1 用 DTB UART 打印日志
→ kernel/src/protect.rs                   // EL1 登记 MMIO reg 范围
→ kernel/src/mmu.rs                       // EL1 建页表并打开 MMU
→ kernel/src/trap.rs::enter_el0()         // EL1 eret 到 EL0
→ libos/src/main.rs::_start()             // EL0 libOS
→ svc #0                                  // EL0 陷入 EL1
→ kernel/src/trap.rs::el1_sync_handler()  // EL1 处理 syscall
→ SYS_MAP_MMIO                            // EL1 授权 EL0 映射 UART MMIO
```

---

## 编译时只需要知道这三步

```text
build.sh
→ 先编译 libos，生成 libos/libos.bin
→ 再编译 kernel，生成 BOOTAA64.efi
→ kmain.rs 用 include_bytes! 把 libos.bin 打进 BOOTAA64.efi
```

所以 UEFI 最终只加载：

```text
BOOTAA64.efi
```

`libOS` 已经被包含在 `.efi` 里面。

---

## 每个文件在哪个 EL 执行

| 文件 | 当前是否执行 | 执行 EL | 作用 |
| --- | --- | --- | --- |
| `kernel/src/main.rs` | 是 | EL2 | UEFI 入口，收集硬件信息，退出 Boot Services，跳 EL1 |
| `kernel/src/boot_info.rs` | 是 | EL2，之后 EL1 读取 | 定义 `BootInfo`，EL2 填内存图/寄存器快照，EL1 读取 |
| `kernel/src/uart.rs` | 是 | EL1 | EBS 后由 DTB 初始化 PL011 MMIO UART；EL2/EBS 前不用它 |
| `kernel/src/vectors.rs` | 是 | EL2、EL1 | 安装 `VBAR_EL2` 和 `VBAR_EL1`，异常入口汇编也在这里 |
| `kernel/src/trap.rs` | 是 | EL2、EL1 | EL2 进 EL1、EL1 进 EL0、EL1 处理 EL0 syscall |
| `kernel/src/kmain.rs` | 是 | EL1 | EL1 外核主逻辑 |
| `kernel/src/mem.rs` | 是 | EL1 | 物理页分配器 |
| `kernel/src/dtb.rs` | 是 | EL1 | 静默查询 PL011，完整解析 DTB，打印设备节点和 `reg` |
| `kernel/src/mmu.rs` | 是 | EL1 | 先开 identity stage-1，再映射 EL1/EL0/DTB/MMIO |
| `kernel/src/protect.rs` | 是 | EL1 | DTB `reg` 登记进 MMIO 保护表，`SYS_MAP_MMIO` 查询它 |
| `libos/src/main.rs` | 是 | EL0 | EL0 libOS 入口，解析只读 DTB，发 `svc #0` |

读代码时按这个表判断：

```text
main.rs 只在 EL2 跑
kmain.rs 基本只在 EL1 跑
libos/src/main.rs 只在 EL0 跑
trap.rs/vectors.rs 跨 EL，用具体函数判断当前 EL
uart.rs 当前只在 EL1 做 EBS 后 MMIO UART
```

---

## EL2 做什么

EL2 代码入口是：

```rust
kernel/src/main.rs::main()
```

EL2 只做启动，不做长期内核逻辑。

执行顺序：

```text
main()
→ boot_info.rs::BootInfo::default()
→ 初始化 UEFI helper
→ UEFI console 打印 pre-EBS
→ 收 framebuffer 地址
→ 收 ACPI/DTB 地址
→ exit_boot_services()
→ boot_info.rs::BootInfo::fill_memmap()
→ boot_info.rs::BootInfo::read_el2()
→ vectors.rs::install_el2()
→ trap.rs::enter_el1_kernel(...)
```

关键点：

- `main.rs` 是 UEFI 入口。
- 当前 CPU 在 EL2。
- EL2 收集启动信息，放进 `BootInfo`。
- EBS 前日志走 UEFI console。
- EBS 后不再调用 UEFI 服务，也不直接碰固定 UART 地址。
- EL2 最后调用 `enter_el1_kernel()` 进入 EL1。

真正进入 EL1 的地方是：

```rust
kernel/src/trap.rs::enter_el1_kernel()
```

它设置：

```text
ELR_EL2  = el1_main 地址
SPSR_EL2 = EL1h 状态
SP_EL1   = EL1 栈
x0       = BootInfo 指针
eret
```

`eret` 执行后，CPU 从 EL2 进入 EL1。

---

## EL1 做什么

EL1 入口是：

```rust
kernel/src/kmain.rs::el1_main()
```

EL1 是真正的外核。

执行顺序：

```text
el1_main()
→ vectors.rs::install_el1()
→ boot_info.rs 读取 BootInfo
→ mem.rs::init_empty()
→ mem.rs::add_range()
→ mem.rs::free_pages_total()
→ 如果 UEFI 没给 DTB: mem.rs::alloc_pages() 分配 DTB 页
→ mmu.rs::create_table()
→ mmu.rs::map_range_2m()
→ mmu.rs::activate()                    // 先开 EL1 identity stage-1
→ dtb.rs::find_pl011_reg()              // 静默找 UART
→ uart.rs::init()
→ mmu.rs::map_block_2m()                // UART 设为 Device memory
→ dtb.rs::parse()
→ protect.rs::register()
→ mem.rs::alloc_pages() 分配 libOS 代码页
→ mem.rs::alloc_page() 分配 EL0 栈页
→ copy_nonoverlapping() 把 libos.bin 拷贝到物理页
→ mmu.rs::map()                         // 映射 EL0 code/stack/只读 DTB
→ trap.rs::enter_el0(..., dtb_user_va)
```

关键点：

- EL1 开始管理物理页。
- EL1 建页表。
- EL1 决定哪些页给 EL0 用。
- EL1 把 `libos.bin` 映射到 EL0 虚拟地址 `0x4000_0000`。
- EL1 把 DTB 只读映射到 EL0 虚拟地址 `0x4020_0000`。
- EL1 通过 `x0` 把 `dtb_user_va` 传给 EL0。

进入 EL0 的地方是：

```rust
kernel/src/trap.rs::enter_el0()
```

它设置：

```text
ELR_EL1  = 0x4000_0000
SPSR_EL1 = EL0t 状态
SP_EL0   = 0x4100_0000
x0       = dtb_user_va
eret
```

`eret` 执行后，CPU 从 EL1 进入 EL0。

---

## EL0 做什么

EL0 入口是：

```rust
libos/src/main.rs::_start()
```

当前 libOS 只是一个最小测试程序。

执行顺序：

```text
_start()
→ 从 x0 拿 dtb_user_va
→ 准备字符串 "[libos] EL0 svc hello"
→ svc(SYS_PUTS, ptr, len)
→ 解析 DTB，找 compatible="arm,pl011"
→ 读取 reg = (base, size)
→ svc(SYS_MAP_MMIO, base, size, UART_VA)
→ 写 UART_VA + PL011_DR，输出 U0
→ svc(SYS_EXIT, 0, 0)
```

`svc #0` 会让 CPU 从 EL0 陷入 EL1。

EL1 接住 syscall 的地方是：

```rust
kernel/src/trap.rs::el1_sync_handler()
```

当前支持：

| syscall | 作用 |
| --- | --- |
| `SYS_PUTC` | 打印一个字符 |
| `SYS_PUTS` | 打印一段 EL0 字符串 |
| `SYS_MAP_MMIO` | 授权并映射 DTB 发现的 MMIO 物理范围 |
| `SYS_EXIT` | 打印退出码并停机 |
