# 外核内存管理设计

## 核心原则：分离保护与管理

| 层级 | 职责 | 管什么 |
| --- | --- | --- |
| **EL2 boot shim** | 启动 | UEFI 收集硬件信息、ExitBootServices、eret 到 EL1 |
| **EL1 外核** | 保护 | 哪个物理页归谁、哪个 MMIO 归谁、是否允许映射 |
| **EL0 libOS** | 管理 | 怎么组织虚拟地址空间、换页策略、COW、共享 |

---

## 按时间顺序的完整链路

### Phase 0：UEFI / EL2 boot shim

UEFI 固件把 `BOOTAA64.EFI` 加载起来时，当前代码运行在 EL2。EL2 这一层不再作为长期外核，只做启动胶水。

#### 0.1 EBS 前收集硬件信息

EL2 boot shim 在 `main.rs` 里先收集：

- GOP framebuffer：保存显存物理基址和大小。
- UEFI config table：保存 ACPI RSDP 和 DTB 地址。
- EBS 前日志：走 UEFI console，不假设 UART MMIO 地址。

EBS 之后不能再调用 UEFI console。后续日志必须等 EL1 从 DTB 找到 UART 后，才能走 MMIO UART。

#### 0.2 ExitBootServices 后保存内存图

`exit_boot_services()` 返回 `MemoryMap`，里面是整台机器每段物理内存的用途清单。

MemoryMap 里的每个条目长这样：

```text
物理基址           页数     类型
0x00000000 ~       1 页     RESERVED
0x00010000 ~       96 页    BOOT_SERVICES_CODE
0x40000000 ~   1048576 页   CONVENTIONAL        // QEMU -m 4G 的 RAM
0x09000000 ~        1 页    MMIO
```

当前 QEMU 4GB DTB 里 `memory@40000000` 的真实数据是：

```text
reg = <0x00000000 0x40000000 0x00000001 0x00000000>
base = 0x40000000
size = 0x100000000    // 4GB
```

启动日志里的 `free=0x3f749c KB` 来自 UEFI `CONVENTIONAL` 页总和，不是直接来自 DTB `memory` 节点。它接近 4GB，但会扣掉 UEFI、内核、ESP 加载、保留区等占用。

EL2 只把 `CONVENTIONAL` 范围记录进 `BootInfo.ranges`，不在 EL2 初始化长期分配器。真正的分配池初始化放到 EL1 外核执行。

| MemoryMap 类型 | 含义 | 当前处理 |
| --- | --- | --- |
| `CONVENTIONAL` | 完全空闲，可用 | 记录进 `BootInfo.ranges` |
| `LOADER_CODE` | `.efi` 代码段 | 不作为空闲页 |
| `LOADER_DATA` | `.efi` 数据/栈 | 不作为空闲页 |
| `BOOT_SERVICES_CODE/DATA` | 固件驱动占用，EBS 后可回收 | 暂不收 |
| `RUNTIME_SERVICES_CODE/DATA` | 固件运行时还在用 | 不能碰 |
| `ACPI_RECLAIM` | ACPI 表 | 暂不收 |
| `ACPI_NVS` | ACPI NVS | 不能碰 |
| `RESERVED` | BIOS/固件保留 | 不能碰 |

#### 0.3 eret 到 EL1 外核

EL2 boot shim 设置 EL1 初始环境：

```rust
msr hcr_el2, (1 << 31)      // HCR_EL2.RW=1，EL1 使用 AArch64
msr sctlr_el1, old & !1     // 先关 EL1 stage-1 MMU
msr elr_el2, el1_main       // eret 后 PC 跳到 EL1 外核入口
msr spsr_el2, 0x3c5         // EL1h，DAIF 全屏蔽
msr sp_el1, el1_stack_top   // EL1 外核栈
mov x0, boot_info_ptr       // x0 传 BootInfo 物理地址
eret
```

此时 EL2 不再处理常规 syscall/fault，只保留 `VBAR_EL2` 做 unexpected trap 诊断。

### Phase 1：EL1 外核

EL1 才是真正的外核。它只做保护和授权，不替 libOS 决定内存策略。

#### 1.1 初始化物理页分配器

EL1 从 `BootInfo.ranges` 重建分配池。当前代码为了避免早期 EL1 栈上放大数组，实际是逐条追加：

```rust
mem::init_empty();
mem::add_range(0x40000000, pages);
mem::add_range(next_base, next_pages);
```

`alloc_page()` 从第一个可用范围头部切一页：

```text
base += 4096
pages -= 1
```

所以物理页所有权从 EL1 外核开始记账。

#### 1.2 解析 DTB，登记 MMIO

EL1 解析 UEFI 提供的 DTB；如果没有，并且是 QEMU 构建，就使用编译进 `.efi` 的 `qemu/qemu-virt.dtb`。

UART 初始化分两步：

```text
先静默查询 DTB:
  find_pl011_reg(dtb_addr) → (base=0x09000000, size=0x1000)

再初始化 EL1 MMIO UART:
  uart::init(base)
```

所以 EBS 后第一条可见日志来自 DTB 发现的 UART，不再来自编译期硬编码地址。

典型设备节点：

```text
pl011@9000000 → reg = (0x09000000, 0x1000)
intc@8000000  → reg = (0x08000000, 0x10000)
pcie@...      → reg = (0x4010000000, ...)
```

这些 MMIO 范围进入保护表，默认不分给 EL0。EL0 想碰设备，必须通过 EL1 授权映射。

#### 1.3 安装 EL1 异常向量

EL1 写 `VBAR_EL1`。来自 EL0 的同步异常会进入 EL1：

```text
EL0 SVC              → EL1 sync handler
EL0 Data Abort       → EL1 sync handler
EL0 InstructionAbort → EL1 sync handler
EL0 IRQ              → EL1 irq handler
```

注意：`SVC`、`HVC`、缺页都属于同步异常，不是 IRQ。IRQ 是异步中断。

#### 1.4 建 EL1 stage-1 页表

EL1 建自己的 stage-1 页表：

- 外核自身和启动期需要的物理地址：identity map，EL1-only。
- UART MMIO：identity map，Device-nGnRE，EL1-only。
- EL0 libOS 代码：映射到用户虚拟地址 `0x4000_0000`，EL0 可访问。
- DTB：只读映射到 EL0 虚拟地址 `0x4020_0000`，让 libOS 自己发现设备。
- EL0 UART MMIO：只有 EL0 调 `SYS_MAP_MMIO(base, size, user_va)` 且 EL1 查保护表通过后才映射。
- EL0 栈：映射到用户栈顶 `0x4100_0000` 附近，EL0 可读写。

真实 PTE 写入、TLBI、页属性选择都在 EL1 做。EL0 不能直接改 `TTBR_EL1/TCR_EL1/MAIR_EL1/SCTLR_EL1`。

#### 1.5 eret 到 EL0 libOS

EL1 设置 EL0 初始状态：

```rust
msr elr_el1, libos_entry_va
msr spsr_el1, 0              // EL0t
msr sp_el0, user_stack_top
eret
```

eret 之后 CPU 在 EL0 执行 libOS。

### Phase 2：EL0 libOS

EL0 libOS 做管理策略，但不直接拥有硬件权限。

当前最小 syscall：

| syscall | 作用 |
| --- | --- |
| `SYS_PUTC` | 让 EL1 打印一个字符 |
| `SYS_PUTS` | 让 EL1 打印一段用户字符串 |
| `SYS_MAP_MMIO` | 请求 EL1 把 DTB 发现的 MMIO 物理范围映射到 EL0 VA |
| `SYS_EXIT` | 退出当前 EL0 测试程序 |

当前 libOS 的 UART 测试流程：

```text
x0 = dtb_user_va
EL0 解析 DTB
EL0 找 compatible = "arm,pl011"
EL0 读取 reg = (base, size)
EL0 调 SYS_MAP_MMIO(base, size, UART_VA)
EL1 查 protect.rs
EL1 写 PTE: UART_VA -> base, Device memory, EL0 可访问
EL0 写 UART_VA + PL011_DR
```

PL011 的寄存器偏移由 driver 知道，不从 DTB 读取：

```text
PL011_DR = 0x00
PL011_FR = 0x18
```

后续再扩展：

| syscall | 作用 |
| --- | --- |
| `SYS_ALLOC_PAGE` | 向 EL1 申请一个物理页 capability |
| `SYS_MAP_PAGE` | 请求 EL1 把授权物理页映射进 EL0 VA |
| `SYS_UNMAP_PAGE` | 请求 EL1 解除映射 |
| page fault upcall | EL1 把缺页事件通知 EL0 pager |

EL0 可以决定“想怎么组织虚拟地址空间”，但最终的授权边界仍由 EL1 执行。

## 当前安全边界

EL0 默认不能访问：

- 未映射的普通内存。
- 未授权的 MMIO。
- EL1-only 页表、外核代码和外核栈。
- 系统寄存器，例如 `TTBR_EL1`、`TCR_EL1`、`MAIR_EL1`、`SCTLR_EL1`、`VBAR_EL1`。

EL1 默认能做：

- 分配和记录物理页所有权。
- 建 stage-1 页表。
- 处理 EL0 的 `SVC` 和缺页。
- 判断 MMIO 是否允许映射。

这就是当前路线的核心：EL2 只启动，EL1 保护，EL0 管理。
