# LiteEth 逐函数翻译整改结果

基准：本地 Linux 6.12.75 的 `drivers/net/ethernet/litex/litex_liteeth.c`。原 C 对照保留；注释/排版不同，代码 token 相同。

## 已修改

| 项目 | 当前实现 |
| --- | --- |
| 9 个入口 | [liteeth.rs](../../libos/src/drivers/liteeth.rs) 按 C 顺序排列；保留参数名、顺序和返回协议，不再用 self 代替 netdev/pdev |
| 20 个 if | 条件、嵌套和依赖调用顺序逐项核对；RX 两个错误分支汇入原 rx_drop；原日志、默认值和释放位置保留 |
| 49 个依赖定义 | 39 个普通函数、10 个宏；C 字符串使用裸指针，保留 NULL/ERR_PTR、输出参数；PTR_ERR 返回 i64，net_ratelimit 返回 i32，free_irq 返回原名称指针 |
| 内存 | netdev/私有区、线性 skb/数据及各 CPU 统计实际堆分配；失败返回 NULL；devm 和明确释放点回收 |
| MMIO | 同名接口查资源、占用物理范围、按页映射并返回含页内偏移的 VA；失败/解绑后逆序回收；驱动不增加后端参数 |
| IRQ | 注册原 handler/dev_id；独立 EL0 线程自动派发；回调后 ACK；free_irq 取消等待并同步在途回调/线程退出 |
| 网络核心 | BUSY 保留同一 skb，IRQ 唤醒后调度重试；接收队列取得 skb 所有权；注销自动调用 stop，之后再回收 devm |
| 应用包装 | [liteeth_runtime.rs](../../libos/src/drivers/liteeth_runtime.rs) 负责 attach/send/receive；不替代原驱动入口 |

## 验证

- `tools/liteeth/check_translation.py`：9 个入口定义、20 个 if 条件/嵌套、依赖调用序列、冻结签名及同名宏。
- 11 项原生驱动测试：分配失败、BUSY、超长丢弃、默认属性、MAC 回退、寄存器顺序及回滚/启停。
- 15 项依赖接口测试：堆所有权、每 CPU 统计、队列重试、MMIO 冲突/页内偏移、IRQ 回调同步与取消阻塞等待等。
- C 宿主对照启用 ASan/UBSan。
- 两版 QEMU 各完成 17 帧、10752 字节；比较帧内容、统计、slot/寄存器顺序和启停顺序。Rust ELF 无原 C 驱动/适配 FFI 符号。
- Rust 应用尚未调用 wait_irq 时，IRQ 服务线程已接收第一帧。

结果见 [对照测试摘要](对照测试摘要.json)；本轮完整日志在 `target/liteeth-comparison/20261026-163330/`。复现：

```sh
python3 tools/liteeth/compare.py --qemu /private/tmp/exo-liteeth-work/build/qemu-system-aarch64
```

检查器不是形式化证明；C 对照也运行于既有精简适配环境，不能替代真实 Linux 内核端到端验证。

## 严格约束尚未全部满足

入口定义与原驱动分支已恢复，依赖完整语义仍有差距，不能把“当前样例跑通”写成“三条全部达标”。

| 差距 | 当前情况 |
| --- | --- |
| Linux 网络核心 | netif_rx 交付目标 L2 核心；没有完整 Linux IP/socket、RPS、per-CPU backlog/softirq、sysfs/rtnetlink 链路发布 |
| IRQ 通用能力 | flags=0 独占 IRQ 可用；IRQF_SHARED 等返回不支持。回调位于 EL0 服务线程，具有不同于 Linux hardirq 的上下文 |
| 模块框架 | 静态 platform 匹配及 probe/remove/devm 生命周期可用；Linux .ko/.modinfo 和模块别名自动加载未实现 |
| OF 框架 | 目标整理节点属性/MAC；没有完整 IRQ domain、延迟探测、NVMEM provider 机制 |
| skb 通用能力 | 线性独占 skb 已实际分配/释放；clone、共享引用及非线性 skb 尚未实现 |
| 随机源 | QEMU/固件 rng-seed 可驱动随机 MAC；缺少种子的目标尚未验证该回退路径 |

上述项目是未完成项，不是对“语义不变”的例外。完整 Linux 依赖语义不能仅靠修改 LiteEth 函数签名恢复。
