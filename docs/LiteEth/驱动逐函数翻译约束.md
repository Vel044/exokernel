# 驱动逐函数翻译约束

后续按固定版本的 Linux 源码逐函数翻译。三条都是验收条件，适用于驱动及其直接调用的依赖接口；现有 Rust 版本需要按此重新核对。

## 约束 1：驱动入口定义、参数和语义不变

- 保留函数名、参数名、参数数量与顺序，以及参数类型的含义和返回协议。
- 保留输入/输出方向、允许为空的条件、上下文、状态变化和资源所有权约定。
- 原函数显式接收 `netdev`、`pdev`、`irq`、`dev_id` 或 `stats`，目标函数也必须保留对应参数；不能擅自改成 `self` 或改成通过返回值传回结果。

例如 Linux 的入口：

```c
static irqreturn_t liteeth_interrupt(int irq, void *dev_id);
static void liteeth_get_stats64(struct net_device *netdev,
                               struct rtnl_link_stats64 *stats);
```

应分别保留 `irq/dev_id`、`netdev/stats` 的参数和用途，以及 `irqreturn_t`、`void` 的返回含义。只保留 `liteeth_interrupt`、`liteeth_get_stats64` 这两个名字不算符合。

## 约束 2：依赖函数定义、参数和语义不变

- 驱动调用的依赖保留原函数名、参数名、参数数量与顺序、类型含义、返回协议和语义。
- 不能增加驱动必须传入的映射后端、注册对象、接收队列等参数，或删除原来的上下文参数。
- 核对成功与失败返回、阻塞与唤醒、回调执行、内存访问顺序、资源占用/释放，以及并发与生命周期要求。
- 实现内部可以接本项目的 syscall；调用处看到的约定必须保留。缺少能力时记为未实现或不符合，不能把空实现、只改标志位或缩小支持范围当成完整实现。

例如 Linux 的接口：

```c
int request_irq(unsigned int irq, irq_handler_t handler, unsigned long flags,
                const char *name, void *dev);
```

目标接口必须保留这五个参数的名字、顺序和用途，不能把首参数改成 `registration`、同时去掉最后的 `dev`。回调需要的上下文也必须能按原约定传入。

“语义不变”要求核对依赖的行为，不只是核对它有没有被调用。比如 `unregister_netdev` 的自动停机、`netif_wake_queue` 的发送调度、分配函数的失败行为，不能因为当前样例没碰到就忽略。

## 约束 3：有意义的分支结构保持一致

- 保留判断条件、分支顺序、嵌套关系和各路径执行的操作。
- 保留成功、失败、忙、丢弃、重试、默认值及资源回收路径，以及对应返回值。
- 保留同一分支内的硬件读写、队列变化、统计和释放操作的先后顺序。
- 不把重要分支折叠成 `?`、`unwrap/expect`、断言或无条件成功；不为方便移植擅自增加、删除、合并或移走分支。

例如 LiteEth 发送忙分支应能逐项对应：

```c
if (!litex_read8(priv->base + LITEETH_READER_READY)) {
    if (net_ratelimit())
        netdev_err(netdev, "LITEETH_READER_READY not ready\n");
    netif_stop_queue(netdev);
    return NETDEV_TX_BUSY;
}
```

需要对照的是 READY 判断、限流判断、日志、停队列和 BUSY 返回，而不是只保留一个最终 BUSY 结果。原有 `goto` 清理路径需要在 Rust 中保留相应控制流及释放顺序的可读对应，不能仅凭“最后会 Drop”略去核对。

## C 与 Rust 的语言差异

“定义不变”指接口定义和行为约定一致，允许按明确的类型映射转换语言语法，例如 C `u32` 对应 Rust `u32`，保留字 `priv` 写成 `r#priv`。指针改为引用或拥有值时，还必须核对空值、别名、可变性、地址稳定性及释放责任，不能自动视为等价。

返回指针改成 `Result`、`NETDEV_TX_BUSY` 改成携带 skb 的枚举、输出参数改成返回对象等，都不是纯语法转换。默认按不符合处理；要改变约束，必须由用户明确修改约束。

## 现有 LiteEth 的已发现差距

本轮已恢复 9 个入口签名、49 个依赖调用定义和 20 个原驱动 if 条件/嵌套；新增 [逐函数翻译检查](../../tools/liteeth/check_translation.py) 和分配失败、IRQ 同步、队列调度测试。

**依赖完整语义仍不能标为全部通过。** Linux 网络栈、共享 IRQ、动态模块等差距列在 [整改结果](逐函数翻译整改结果.md)；测试跑通不能抵消这些约束。
