# 驱动迁移协作入口

目标是先研究 **Linux 驱动源码 → 可分析的 IR**。目标代码生成方式尚未确定；当前 exokernel 接口用于帮助识别必须保留的语义，不要求前端立即绑定这套 ABI。

## 建议阅读顺序

1. [仓库首页](../../README.md)：目录边界、构建条件和已有组件。
2. [接口导读](target-interfaces.md)：用 UART 理解 MMIO/IRQ，再看 DMA。
3. [会议提纲](meeting.md)：现场讨论 IR 范围、样例、验收与会后分工。

## 第一阶段分别交付什么

| 维护者提供 | IR 工具开发者提供 | 双方一起确定 |
| --- | --- | --- |
| 可 fork 的主线源码、接口说明、样例走读 | 固定 Linux 版本与配置的解析入口 | IR 是 LLVM IR、专用语义层，还是二者组合 |
| UART 与 DMA 的目标侧调用链 | 一个真实 Linux 函数的 IR 与源码映射 | 首个样例、支持范围、成功标准 |
| 当前限制及已有验收证据 | 依赖清单、失败路径、未支持诊断 | 是否需要在第一阶段运行 exokernel |

建议首个里程碑是“一个样例可复现、可人工核对”，而不是“整个 xHCI 自动迁移”。UART 只承担讲解；DMA 样例承接研究目标。目标侧还没有稳定承诺的统一 DeviceHandle/IOMMU 接口，不应把这些当成现有能力。

## 分支和提交

源码与文档直接维护在 `main`。Fork 默认主线后即可开始工作。提交分开组织为前端、IR 定义、样例和验证说明；记录 Linux commit、架构、配置、编译器版本以及实际命令。

首次独立检出已发现外部 `rutorch` path 依赖缺失，尚不能仅靠 fork 完成构建；详见[首页构建说明](../../README.md)。本轮可先阅读接口与开发 Linux → IR 前端，独立内核运行环境留作后续准备。

目前不要搬动内核与 libOS 的物理目录：Cargo path、链接脚本和 ELF 嵌入均依赖现有布局。先用入口文档整理阅读结构，功能拆分在明确接口后逐步进行。
