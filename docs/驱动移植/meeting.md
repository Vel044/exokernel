# 驱动迁移首次会议提纲

当前驱动是围绕本项目内核接口适配 Rust 驱动库完成的，并没有以 Linux 驱动为对照实现。会议展示的是现有目标环境与接口；Linux 源码分析是后续工作。

## 开场可以这样说

> 今天我先介绍一下现有用户态驱动怎么接到内核上。用 UART 看最简单的寄存器读写和中断，再用 xHCI 看复杂一些的驱动怎样接入。这样你能知道目标系统需要提供哪些能力。最后我们一起定一下，后续从 Linux 驱动生成 IR，第一步做到什么程度。现有代码并不是对照 Linux 移植的，所以今天主要讲这边已经有的接口。

## UART：讲一条完整路径（6 分钟）

先说明 PL011 驱动库操作寄存器，本项目适配层为它准备资源与中断通知。围绕 `run` 讲三件事：

1. **设备从哪来：**内核把获授权的 UART 地址、长度和 IRQ 信息传给用户态。
2. **如何访问：**用户态请求 MMIO 映射，随后驱动库通过映射地址直接读写寄存器。
3. **如何等待和处理：**线程等待 Notification；输入触发中断后被唤醒，读取字符、回显、清设备中断，再 ACK。

```text
输入字符 → UART 中断 → 内核投递 Notification
        → 用户态读写 FIFO → 清设备中断 → IRQ_ACK
```

口头补一句：内核入口会先屏蔽 IRQ 并完成 GIC EOI，用户态 ACK 用于重新开放 IRQ。寄存器位定义、页表和 GIC 内部实现留到提问时再展开。

## xHCI：展示复杂驱动怎样接入（8 分钟）

先定位层次：xHCI 控制 USB 主控制器，USB 串口和 UVC 在它上面。现有实现使用 CrabUSB，本项目负责把它接到外核资源接口和用户态执行器。

- **初始化，约 3 分钟：**从 `xhci.rs::initialize` 看设备资源发现、MMIO 映射、Notification 绑定，以及创建和初始化 CrabUSB Host。
- **请求完成，约 3 分钟：**驱动库组织请求并通知控制器；Future 等待期间由执行器等待通知。设备完成后，用户态消费 Event Ring、ACK IRQ，再继续推进 Future。
- **DMA，约 2 分钟：**只说明描述符和数据缓冲区需要设备可访问的内存；CPU 使用 VA，设备使用 DMA address；提交前数据需可见，释放前设备必须用完。指出 [dma.rs](../../libos/src/drivers/dma.rs) 是适配入口即可。

```text
EL0 驱动库提交请求 → xHCI 执行 → Event Ring / IRQ
→ 内核投递 Notification → EL0 消费事件 → ACK → 推进 Future
```

DMA 不单独设专题。分配算法、bounce buffer、缓存维护和屏障细节放在[接口导读](target-interfaces.md)供会后阅读；现场重点是让对方知道驱动接入需要哪些接口。

## 后续工作的方向（5 分钟）

下面是希望共同探索的流程，尚未实现，也不要求现在确定目标代码语言：

```text
选定的 Linux 驱动源码与构建配置
→ 解析、生成 IR，标出设备操作与 Linux 环境依赖
→ 后续研究：哪些依赖可接到外核/libOS 接口，哪些还需适配
→ 更后续：生成目标代码并验证设备行为
```

现有 UART/xHCI 实现提供目标环境的参考。后续应比较“需要什么能力、接口语义能否满足”，不要求 Linux 函数与当前 Rust 函数逐个对应。

第一步期望能从选定路径里看出：它访问什么资源、调用哪些环境接口、正常流程和失败清理怎么走。IR 的具体形式由双方商定；输出里应保留源码位置，并把不能处理的依赖明确列出。

| 项目         | 建议约定                                                                      |

| 输入         | 固定 Linux 版本、架构和配置，从一个驱动的一条小路径开始；会上选定具体样例     |

| 第一阶段验收 | 按记录的命令可复现；人工能核对关键设备操作、分支和资源清理是否保留            |
| 暂不纳入     | 整个 xHCI/USB 栈自动转换、目标代码生成、完整驱动运行验收                      |
| 分工         | 我提供目标接口说明并解释现有适配；对方做 Linux 前端/IR 原型；双方一起核对首例 |

结束前只需定下：**首例选哪条路径、IR 输出形式、首轮交付与下次交流时间。** 如果本轮研究仍以 DMA 为重点，就选包含 DMA 分配与释放的小路径，不必因此在本次会议展开 DMA 专题。
